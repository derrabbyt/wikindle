# Target architecture

You’ll end up with:

```text
Angular SPA
https://cf-angular-demo-web.pages.dev
        │
        ▼ HTTPS GET
Cloudflare Worker API
https://cf-angular-demo-api.<your-subdomain>.workers.dev
        │
        ▼ Hyperdrive
Neon PostgreSQL
```

Cloudflare Pages officially supports Angular static deployments, while Hyperdrive connects Workers to external PostgreSQL databases and handles connection pooling. Cloudflare recommends `pg`/node-postgres for JavaScript or TypeScript Workers using Hyperdrive. ([Cloudflare Docs][1])

For this first version, the browser receives **read-only public data**. There is no public database write endpoint, no database password in the frontend, and the PostgreSQL role used by the Worker gets only `SELECT` permission.

# 3. Create PostgreSQL on Neon

## Create the database

In Neon:

1. Create a project named `cf-angular-demo`.
2. Use the default database, normally `neondb`.
3. Open **SQL Editor**.
4. Run this schema.

Create `db/schema.sql`:

```sql
CREATE TABLE IF NOT EXISTS public.demo_items (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name TEXT NOT NULL CHECK (char_length(name) BETWEEN 1 AND 100),
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

INSERT INTO public.demo_items (id, name)
VALUES
    (1, 'Angular frontend'),
    (2, 'Cloudflare Worker backend'),
    (3, 'Neon PostgreSQL database')
ON CONFLICT (id) DO NOTHING;
```

Paste it into Neon’s SQL Editor and execute it.

Neon provides its connection string through the project’s **Connect** dialog and supports executing setup SQL through its SQL Editor. ([Neon][3])

## Create a dedicated database user

In Neon, open **Roles** and create:

```text
hyperdrive_reader
```

Use a generated password and save it temporarily in a password manager.

Run the following as the database owner in the SQL Editor:

```sql
GRANT CONNECT ON DATABASE neondb TO hyperdrive_reader;
GRANT USAGE ON SCHEMA public TO hyperdrive_reader;
GRANT SELECT ON TABLE public.demo_items TO hyperdrive_reader;
```

Verify that this role cannot write:

```sql
SET ROLE hyperdrive_reader;

SELECT * FROM public.demo_items;

-- This should fail:
INSERT INTO public.demo_items (name)
VALUES ('This must not be inserted');

RESET ROLE;
```

The failed insert is expected and confirms that a compromised API cannot modify the database through these credentials.

## Obtain the direct connection string

In Neon’s **Connect** dialog:

1. Select database `neondb`.
2. Select role `hyperdrive_reader`.
3. Choose a connection string.
4. Turn **connection pooling off** for this connection.
5. Copy the resulting direct connection string.

It will resemble:

```text
postgresql://hyperdrive_reader:PASSWORD@ep-example.eu-central-1.aws.neon.tech/neondb?sslmode=require
```

Cloudflare’s Neon integration specifically instructs you to use a dedicated role and Neon’s direct, non-pooled connection string because Hyperdrive itself provides the connection pooling. ([Cloudflare Docs][4])

Do not commit this connection string anywhere.

## Create `apps/api/src/index.ts`

```ts
import { Client } from "pg";

interface Env {
  HYPERDRIVE: Hyperdrive;
}

interface DemoItem {
  id: number;
  name: string;
  created_at: Date;
}

const commonHeaders: Record<string, string> = {
  "Access-Control-Allow-Origin": "*",
  "Access-Control-Allow-Methods": "GET, OPTIONS",
  "Access-Control-Allow-Headers": "Content-Type",
  "Access-Control-Max-Age": "86400",
  "Cache-Control": "no-store",
  "Content-Type": "application/json; charset=utf-8",
  "Referrer-Policy": "no-referrer",
  "X-Content-Type-Options": "nosniff",
  "X-Frame-Options": "DENY",
  "Permissions-Policy": "camera=(), microphone=(), geolocation=()",
  "Content-Security-Policy": "default-src 'none'; frame-ancestors 'none'",
};

function jsonResponse(data: unknown, status = 200): Response {
  return new Response(JSON.stringify(data), {
    status,
    headers: commonHeaders,
  });
}

export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const url = new URL(request.url);

    if (request.method === "OPTIONS") {
      return new Response(null, {
        status: 204,
        headers: commonHeaders,
      });
    }

    if (request.method !== "GET") {
      return jsonResponse({ error: "Method not allowed" }, 405);
    }

    if (url.pathname === "/api/health") {
      return jsonResponse({
        status: "ok",
        service: "cf-angular-demo-api",
      });
    }

    if (url.pathname !== "/api/items") {
      return jsonResponse({ error: "Not found" }, 404);
    }

    const client = new Client({
      connectionString: env.HYPERDRIVE.connectionString,
    });

    try {
      await client.connect();

      const result = await client.query<DemoItem>(`
        SELECT id, name, created_at
        FROM public.demo_items
        ORDER BY id ASC
        LIMIT 50
      `);

      return jsonResponse({
        database: "PostgreSQL",
        source: "Cloudflare Worker via Hyperdrive",
        items: result.rows,
      });
    } catch (error: unknown) {
      const message =
        error instanceof Error ? error.message : "Unknown database error";

      console.error("Database request failed:", message);

      // Deliberately do not return database details to the browser.
      return jsonResponse({ error: "Unable to load demo data" }, 500);
    } finally {
      try {
        await client.end();
      } catch {
        // The request result is more important than a cleanup error.
      }
    }
  },
} satisfies ExportedHandler<Env>;
```

Why wildcard CORS is acceptable here: this endpoint exposes intentionally public, read-only demo data, accepts only `GET`, uses no cookies and has no authenticated operations. Once you add authentication or private data, replace `*` with your exact frontend origin.

Cloudflare recommends creating a database client per Worker request because Hyperdrive manages the underlying connection pool. ([Cloudflare Docs][5])

## Replace `apps/web/src/app/app.ts`

```ts
import { DatePipe } from "@angular/common";
import { Component, OnInit, signal } from "@angular/core";
import { API_BASE_URL } from "./api-config";

interface DemoItem {
  id: number;
  name: string;
  created_at: string;
}

interface ItemsResponse {
  database: string;
  source: string;
  items: DemoItem[];
}

@Component({
  selector: "app-root",
  imports: [DatePipe],
  templateUrl: "./app.html",
  styleUrl: "./app.css",
})
export class App implements OnInit {
  readonly items = signal<DemoItem[]>([]);
  readonly loading = signal(true);
  readonly error = signal<string | null>(null);
  readonly source = signal("");

  ngOnInit(): void {
    void this.loadItems();
  }

  async loadItems(): Promise<void> {
    this.loading.set(true);
    this.error.set(null);

    try {
      const response = await fetch(`${API_BASE_URL}/api/items`, {
        method: "GET",
        headers: {
          Accept: "application/json",
        },
      });

      if (!response.ok) {
        throw new Error(`API returned HTTP ${response.status}`);
      }

      const payload = (await response.json()) as ItemsResponse;

      this.items.set(payload.items);
      this.source.set(payload.source);
    } catch (error: unknown) {
      console.error(error);
      this.error.set("The backend or database could not be reached.");
    } finally {
      this.loading.set(false);
    }
  }
}
```

# 10. Add GitHub Actions CI/CD

Create `.github/workflows/deploy.yml`:

```yaml
name: CI and deploy

on:
  pull_request:
  push:
    branches:
      - main
  workflow_dispatch:

permissions:
  contents: read
  deployments: write

concurrency:
  group: production-${{ github.ref }}
  cancel-in-progress: true

jobs:
  verify:
    name: Verify frontend and backend
    runs-on: ubuntu-latest

    steps:
      - name: Check out repository
        uses: actions/checkout@v6

      - name: Set up Node.js
        uses: actions/setup-node@v5
        with:
          node-version: 22
          cache: npm
          cache-dependency-path: |
            apps/api/package-lock.json
            apps/web/package-lock.json

      - name: Install backend dependencies
        run: npm ci
        working-directory: apps/api

      - name: Type-check backend
        run: npm run typecheck
        working-directory: apps/api

      - name: Install frontend dependencies
        run: npm ci
        working-directory: apps/web

      - name: Build frontend
        run: npm run build -- --output-path dist/cloudflare
        working-directory: apps/web

  deploy:
    name: Deploy production
    needs: verify

    if: >
      github.event_name != 'pull_request' &&
      github.ref == 'refs/heads/main'

    runs-on: ubuntu-latest

    steps:
      - name: Check out repository
        uses: actions/checkout@v6

      - name: Deploy Worker API
        uses: cloudflare/wrangler-action@v3
        with:
          apiToken: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          accountId: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}
          workingDirectory: apps/api
          command: deploy

      - name: Set up Node.js
        uses: actions/setup-node@v5
        with:
          node-version: 22
          cache: npm
          cache-dependency-path: apps/web/package-lock.json

      - name: Install frontend dependencies
        run: npm ci
        working-directory: apps/web

      - name: Build frontend
        run: npm run build -- --output-path dist/cloudflare
        working-directory: apps/web

      - name: Normalize Angular output
        shell: bash
        working-directory: apps/web
        run: |
          set -euo pipefail

          rm -rf dist/pages
          mkdir -p dist/pages

          if [ -d dist/cloudflare/browser ]; then
            cp -a dist/cloudflare/browser/. dist/pages/
          else
            cp -a dist/cloudflare/. dist/pages/
          fi

          test -f dist/pages/index.html

      - name: Deploy Angular frontend
        uses: cloudflare/wrangler-action@v3
        with:
          apiToken: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          accountId: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}
          workingDirectory: apps/web
          command: pages deploy dist/pages --project-name=cf-angular-demo-web --branch=main
          gitHubToken: ${{ secrets.GITHUB_TOKEN }}
```

The official Cloudflare Wrangler action supports both Workers and Pages deployments, including monorepo working directories. ([Cloudflare Docs][9])

# 11. Create the Cloudflare deployment token

In Cloudflare:

1. Open **Account API Tokens**.
2. Create a custom token.
3. Add the **Edit Cloudflare Workers** policy.
4. Add `Account → Cloudflare Pages → Edit`.
5. Restrict it to only your Cloudflare account.
6. Copy the token.

Cloudflare recommends scoping CI tokens to the smallest possible account access and storing the token in the CI provider rather than the repository. ([Cloudflare Docs][9])

In GitHub, open:

```text
Repository
→ Settings
→ Secrets and variables
→ Actions
```

Create these repository secrets:

```text
CLOUDFLARE_API_TOKEN
CLOUDFLARE_ACCOUNT_ID
```

Do **not** add the Neon database password to GitHub. Hyperdrive already holds the database credentials, and the Worker repository contains only the Hyperdrive binding ID.

## Security properties of this demo

* The PostgreSQL password never enters the browser or Git repository.
* Hyperdrive owns the database connection credentials.
* The Worker database role is read-only.
* The API accepts only `GET` and `OPTIONS`.
* SQL is fixed rather than constructed from user input.
* Internal database errors are logged but not exposed to users.
* The Cloudflare CI token is stored in GitHub Secrets and scoped to one account.
* Pull requests cannot deploy production.
* The public API returns only deliberately public demo records.
